== Operational repairs

The starting WSL installation had two stopped workers, a stopped Windows
bridge service, an obsolete completed bootstrap checkpoint and an inconsistent
local credential source. Only Portainer and Nexus were deployed initially.

* Retained the completed old checkpoint for review; its source and Python
  identities differ from the current candidate. No checkpoint was forged.
* Restored the workers and selected the previously exercised 10/4/2 GiB node
  allocation within the PC's 21 GB WSL allocation and eight CPU threads.
  The operator-specific infrastructure copy is under
  `.tiny-swarm-world/local/wsl-infra` in the remote candidate.
* Restored and upgraded the owned `TinySwarmWorldWslBridge` service through
  its shipped installation action, preserving its existing service account.
  Fresh inventory reported bridge, routing and agent ready with no blockers.
* Disabled WSL's additional `localhostForwarding` in the PC's `.wslconfig`.
  Windows access uses the explicit managed portproxy bridge. The previous
  configuration was retained and WSL was restarted.
* Added the interactive logon task `TinySwarmWorld-Ubuntu-KeepAlive` to hold an
  ordinary-user `sleep infinity` session in the selected distribution.
  Without a retained session, WSL stopped between short invocations despite
  its systemd services. The task is running; startup before user logon and
  complete Windows reboot persistence were not qualified.
* Enabled `boot.autostart` for the three owned Incus nodes. Restarted Incus
  after the WSL transition and observed the three nodes running.
* Configured `generateHosts=false` in `/etc/wsl.conf` to retain the managed
  hosts file on future distribution starts. This setting's next-start effect
  is not separately qualified by a subsequent restart.
  The reviewed hosts payload, SHA-256
  `cdccd998ed7dcc8271fca1e5f87db0d2f59bdb944d9ae2ff2184518eb4dcda93`,
  was installed through the existing protected-file helper after backing up
  the previous file. The aggregate preparation path had refused earlier
  changing snapshots; its guards were not changed. Final shipped preparation
  `--preflight` returned exit 0 with Linux networking and the Windows bridge
  ready. Its log is `preparation-final.log`.
* Installed the canonical WSL CA in the Windows machine root trust store.
  Browser/API verification uses that same WSL CA.
* Preserved and removed the candidate's legacy `.env` from its temporary Git
  index and public source scan. Private copies reside under
  `.tiny-swarm-world/local`; secret checks were retained.
* Selected the existing working Portainer credential in the private
  `.tiny-swarm-world/local/wsl-installation.env` operator file.

Windows IP Helper was restarted during routing diagnosis. Its previously
running Tailscale dependency was restarted and observed running afterward.
No Windows reboot was performed.
