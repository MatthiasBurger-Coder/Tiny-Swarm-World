operations, development, quality, security, audits, evidence and releases.

Use this index for navigation or read the
link:document.adoc[continuous Product Handbook]. Both use the same canonical
source files. Reference material and historical records are linked from the
part catalogues rather than copied into a second handbook.

== Source ownership and directory assignment

The handbook parts define both the documentation hierarchy and physical
directory layout. Every specialist source is stored below its owning part in
`handbook/`. Each part's `README.adoc` lists its sources, including machine
readable artifacts. Links, tools and documentation consumers use these paths.

[options="header"]
|===
| Directory below `handbook/` | Sources stored there
| `01-product/` | `contracts/`, `epics/`
| `02-architecture/` | `arc42.adoc`, `arc42/`, `arc42-template.adoc`; includes architecture requirement baselines, ADRs, analyses, configuration contracts and deployment references.
| `03-user-guide/` | `user_guide/`
| `04-operations/` | `system/`, `Howto.adoc`, `manuals/operator-manual.md`
| `05-development/` | `process/`, `workflow/`, developer and tool manuals; includes `process/skills/audit/` for the skill registry.
| `06-quality-security/` | `audit/`, `qms/`, `security/`, `governance/`, security and audit manuals
| `07-evidence-release/` | `evidence/`, `traceability/`, `release/`, `reviews/`, live-validation manual
|===

`README.adoc` and `document.adoc` stay at the documentation root as the master
index and continuous edition. Every part has its own `README.adoc`.
The link:handbook/05-development/documentation-layout-migration.md[migration map]
records previous source locations. Historical source snapshots and hash
manifests retain their recorded paths and bytes; those paths identify their
original revision rather than the current filesystem layout.

Repository-root documents remain at their required discovery paths.
link:../README.md[README.md] is the short product entry point;
link:../AGENTS.md[AGENTS.md] and link:../QUALITY.md[QUALITY.md] govern
agent work and verification and are referenced from Part 5;
link:../OPERATIONAL_READINESS_CHECKLIST.md[the readiness checklist] and
link:../CHANGELOG.md[CHANGELOG.md] belong to Part 7.
link:../commit_push.md[Publication instructions] belong to Part 5.
Component-local README files and tool instructions stay beside their code;
Part 5 links the repository and tool responsibilities.

== Maintenance rules

. Give every new document or evidence artifact one primary handbook part.
  Store it below that part's directory and add a link to its `README.adoc`
  source catalogue in the same change. Do not create parallel specialist
  directories at the documentation root.
. Keep one canonical source for each procedure, contract, policy or register.
  Other chapters link to it; aggregates include existing sources.
. Update this master index when a part or source-directory responsibility changes.
  Keep `document.adoc` aligned with the same seven parts.
. Keep architecture in arc42's twelve sections. Link from architecture to
  operational manuals, audit registers and evidence in their handbook parts.
. Keep planned requirements, implemented behavior, verification results and
  historical decisions distinct. Moving or indexing a record does not change
  its status or qualify a new candidate.
. Preserve stable finding IDs, ADR history, issue scope, evidence revisions and
  source hashes. Retarget maintained links and path consumers when sources
  move; preserve the recorded content of historical source and hash snapshots.
. Keep secrets, private host details and raw runtime evidence out of committed
  documentation. Follow link:handbook/07-evidence-release/evidence/redaction-rules.md[the redaction rules].
. Maintain repository documentation in English and run checks according to
  link:../AGENTS.md[AGENTS.md] and link:../QUALITY.md[QUALITY.md].
