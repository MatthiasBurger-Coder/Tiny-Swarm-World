The operator amendment to issue #427 makes these the mandatory live qualification scenarios; Ubuntu 24.04 remains locally supported but its live release qualification is separate. Existing-platform reconciliation also passed on the supplied Ubuntu 26.04.1 VM. See protected local issue evidence for run IDs, source digests, exact phases and redacted results.

The clean-host qualification used a separate VM from an official Ubuntu 26.04.1 image with zero existing Tiny Swarm World nodes, services, configuration or evidence. The stock image first blocked read-only preflight because bridge netfilter/forwarding were absent. The operator explicitly applied and persisted the documented kernel settings, ran the separate `prepare_linux.sh` with exact consent for missing packages and Python dependencies, initialized Incus storage/networking, and granted the installation account Incus access. Only then did the installer first run. The VM had eight CPU threads, 24 GiB nominal RAM and a 220 GiB nominal root volume for the `service-access` profile.

The first `./install.sh --headless --non-interactive-live-approval` run exited 0, created three managed Incus nodes and deployed the selected Swarm services with all setup verification phases complete. The identical second run exited 0 with the same node identities and creation times, stable service replicas and no reset. On a disposable checkpoint, a controlled `Ctrl+C` during artifact bootstrap produced exit 130 and a protected setup result; a subsequent preflight and installer run exited 0 and restored a deliberately removed dashboard service to `1/1`, with no reset or node replacement. An additional final-source healthy rerun exited 0 and preserved before/after hashes for ten present configuration/credential-source files, all 724 host package entries, four Swarm secret IDs, two Swarm config IDs and the three managed node creation times. The first two runs used a test-only source snapshot; the interruption, recovery and additional healthy rerun used a later test-only source commit containing the final signal-handling correction. A bounded scan of ten earlier installer/setup logs against fourteen catalog secret values found zero matches; the additional rerun log was outside that scan. The one-shot Pulsar Manager bootstrap displayed `0/1` after successful setup verification; browser-level acceptance of every endpoint was outside this run. The test VM was shut down; the existing operator VM and its three-node Swarm were restored. Its DHCP address changed after restart.

Use an isolated, initially clean Ubuntu 26.04 LTS x86_64 host with at least eight CPU threads, 15 GiB RAM and 150 GiB free disk for the service-access issue-completion profile. Record the repository commit or immutable source digest, host release, selected service profile, redacted evidence paths and exit codes. Confirm zero Tiny Swarm World managed nodes, services, configuration and prior installation evidence before the first run; record the initial host package inventory. Preserve any operator-owned Incus or Docker resources. Do not run destructive reset or container cleanup as part of this protocol without separate explicit intent. A host with an existing managed platform can establish a reconciliation result but cannot establish a clean first-install result. A reset on such a host leaves package and Incus host state behind and is not equivalent to a clean host.

1. Verify `cat /etc/os-release`, `uname -m`, CPU, memory and free disk. Confirm Python 3.12 or newer, sudo permission when packages are missing, host networking and required kernel controls.
   If the stock host lacks bridge netfilter or IPv4 forwarding, record the blocked preflight first, then apply the operator-owned kernel steps from the installation guide and verify persistence after reboot.
2. Run `./prepare_linux.sh --preflight` and `./prepare_linux.sh --dry-run`. Assert that neither creates a virtual environment, APT change, runtime evidence file or managed node.
3. Run `./prepare_linux.sh`, review the exact package list and type `yes` for missing host packages or local Python dependencies. Record its protected evidence path and verified package state. Confirm host Docker Engine and Compose were not installed for the Incus profile.
   The host operator then initializes Incus storage and bridge networking, grants the installer user access, and verifies that no Tiny Swarm World managed nodes exist. These actions and their results are part of the clean-host prerequisite record.
4. Run `./install.sh --preflight` and `./install.sh --dry-run`. Assert host, configuration, credential and setup checks run without reset, Python bootstrap or deployment mutation. Resolve any reported prerequisites.
5. Run `./install.sh --headless --non-interactive-live-approval` only with live approval for this host. Record the setup exit and protected evidence. Verify managed Incus nodes, Docker/Swarm inside nodes, selected service stacks, service health and operator access endpoints. Classify partial or degraded results explicitly.
6. Run the same native installer a second time from the same source and profile. Compare managed node identities and creation times, configuration and credential fingerprints without recording secret values, package inventory and service health. Require successful verification without `platform reset` or destructive replacement.
7. Test an interrupted installation only on an isolated snapshot: interrupt after a recorded stage, inspect confirmed and uncertain effects, rerun preflight and installation, and verify convergence without broad cleanup. Restore the snapshot when the test would affect operator-owned state.
8. On a separate disposable snapshot, exercise unsupported distribution/version, insufficient disk and missing sudo conditions. Each must stop before mutation with an actionable diagnostic and nonzero exit.

Redact user names, addresses, tokens, secrets, raw command output and host-specific paths before adding release evidence.
