= ADR: Traefik HTTPS Ingress With Existing CA

*Date:* 2026-06-09
*Status:* Superseded on 2026-08-23 by `adr-traefik-managed-or-operator-ca.adoc`
*Decision makers:* Tiny Swarm World architecture governance; original named
decision makers were not recorded in this ADR.

== Supersession Note

This ADR originally required an operator-provided existing CA and rejected
automatic CA generation. Classic Public Beta RC1 live/E2E stabilization showed
that this restriction no longer matches the installation goal: a fresh local
installation must be able to converge to trusted HTTPS without a separate
manual PKI bootstrap step.

The replacement decision is
`documentation/arc42/09_decisions/adr-traefik-managed-or-operator-ca.adoc`.
It keeps the Traefik ingress and security boundaries defined here, but changes
certificate ownership to the following precedence:

. explicit operator CA configuration has priority;
. otherwise Tiny Swarm World generates and manages a local CA;
. private keys remain in protected local state or an approved secret store;
. installer, runtime, Traefik and E2E consume one canonical certificate/trust
  contract.

This file remains as architectural history. New implementation and review work
MUST use the superseding ADR.

== Original Context

Tiny Swarm World is a Linux/WSL-only Python automation project for local
Docker Swarm infrastructure on the LXC-native provider path. The migration
changes routing ownership and TLS behavior:

* Traefik becomes the centralized ingress component.
* HTTP redirects to HTTPS.
* LXC public exposure converges on ports `80` and `443`.
* Docker Swarm service routing is represented through explicit Traefik
  configuration or labels.

== Still-Valid Security And Ingress Decisions

The following constraints remain valid under the superseding ADR:

* The migration remains Docker Swarm-first and LXC-native.
* Traefik is a Deployment responsibility, not a product microservice.
* Public LXC exposure for the ingress path is limited to ports `80` and `443`.
* Traefik defines `web` on `:80` and `websecure` on `:443`.
* HTTP traffic redirects to HTTPS.
* `exposedByDefault=false` is required.
* `--api.insecure=true` is forbidden.
* CA private keys, certificate private keys, raw PEM payloads, credential
  values, local resolver files, local IP addresses and host-specific absolute
  paths must not be committed or persisted in evidence.
* Certificate validation records summary fields only: CN, SAN DNS names,
  issuer, validity, KeyUsage, ExtendedKeyUsage and chain verification result.
* Hostname/trust-store mutation requires explicit operator consent and
  rollback.
* Live verification remains opt-in and writes only redacted evidence under
  ignored `.tiny-swarm-world/evidence/**` paths.

The administrative dashboard remains available only through the dedicated
`Host(traefik.tsw.local)` HTTPS router on `websecure`. It uses BasicAuth with
the Docker secret named by `TSW_TRAEFIK_GUI_USERS_SECRET_NAME`. There is no
additional insecure dashboard port.

== Superseded Certificate Ownership Decision

The original decision required existing CA material to be operator-provided and
rejected generated CA material. That part of this ADR is no longer normative.

The superseding ADR permits managed local CA generation when no complete
external CA configuration is present, while preserving external/operator CA
precedence and all private-key/redaction boundaries.

== Consequences

Implementation must follow the replacement ADR for CA selection, managed PKI,
canonical trust-bundle resolution, installer/runtime consistency and RC1 E2E
verification. The security rules above continue to apply.
