= Infisical Silent Setup

Tiny Swarm World bootstraps the local self-hosted Infisical instance with the
official `infisical bootstrap` CLI command. The greenpath must not require the
first-start setup screen and must not automate browser clicks or write directly
to the Infisical database.

== Configuration

The local service declaration is in `infra/config/services.yml`:

[source,yaml]
----
services:
  infisical:
    enabled: true
    mode: self_hosted
    bootstrap:
      enabled: true
      organization: "Tiny Swarm World"
      admin_email: "admin@tiny-swarm.local"
      admin_first_name: "Tiny"
      admin_last_name: "Admin"
      password_source: "resolved_bootstrap_input"
    endpoint:
      internal_url: "http://infisical:8080"
      external_url: "http://localhost:17080"
----

The preferred operator browser route is `https://infisical.tsw.local` through
Traefik. The direct `http://localhost:17080` endpoint is retained as a
diagnostic access path for bootstrap. In the current
self-hosted service-access workflow, `TSW_INFISICAL_URL` must resolve to
`localhost`, `127.0.0.1`, or `::1`; a remote endpoint is an external-provider
configuration and is rejected until a separate integration exists.

== Required Environment

`./install.sh` uses the `internal-test` catalog-backed path by default.
Credential resolution is centralized: an applicable ready secure source wins,
then an explicit operator value, then the deterministic catalog default.
Self-hosted Infisical is never queried for the values needed to start itself.
An operator may provide these values through the protected override file
selected by `TSW_INSTALL_ENV_FILE` or through the process environment:

* `TSW_INFISICAL_LOGIN_EMAIL`
* `TSW_INFISICAL_BOOTSTRAP_ADMIN_PASSWORD`
* `TSW_INFISICAL_ENCRYPTION_KEY`
* `TSW_INFISICAL_AUTH_SECRET`
* `TSW_INFISICAL_POSTGRES_PASSWORD`
* `TSW_INFISICAL_REDIS_PASSWORD`

The catalog supplies all normal internal-test startup values. An operator may
override any applicable value through `TSW_INSTALL_ENV_FILE` or the process
environment. Missing external values, empty overrides, and Infisical write
failures abort the run before deployment can continue.

The normal catalog-backed path is stateless with respect to credentials: it
does not create a credential or recovery file. An explicit bootstrap
override is an operator input only and must be stored on a WSL-native Linux
filesystem with a `0700` parent directory and `0600` file permissions.

== Bootstrap Behavior

The installer runs the official CLI bootstrap behavior equivalent to:

[source,bash]
----
infisical bootstrap \
  --domain=http://localhost:17080 \
  --email=admin@tiny-swarm.local \
  --password=<redacted> \
  --organization="Tiny Swarm World" \
  --ignore-if-bootstrapped
----

The `--ignore-if-bootstrapped` flag keeps reruns idempotent. If the instance is
already initialized, the run records `already_bootstrapped` instead of
recreating users.

After the service is ready, the post-bootstrap synchronization phase may read
existing Infisical values and retain them as the `vault` source. It is separate
from bootstrap and cannot supply self-hosted startup inputs retroactively.

`TSW_INFISICAL_PROVIDER_MODE=external` is rejected by the current
self-hosted service-access workflow. An external Infisical deployment requires
a separate adapter and readiness/deployment contract before it can be used.

== Evidence

Sanitized evidence is written under `.tiny-swarm/evidence/infisical/`:

* `bootstrap-result.json`
* `healthcheck.log`
* `install-summary.md`

Evidence redacts passwords, auth secrets, encryption keys, Redis secrets, and
database connection secrets.

== Reset Behavior

The governed fresh-install reset is still controlled by `./install.sh
--confirm-reset` or the interactive `RESET_TINY_SWARM_PLATFORM` confirmation.
Resetting managed platform state may remove containers and volumes. The next
install reuses operator values or catalog defaults for bootstrap; no credential
file is generated as a side effect.

== Security Notes

Do not print bootstrap passwords, machine identity tokens, auth secrets,
encryption keys, or database connection strings. If the Infisical CLI is
missing, the workflow stops with `infisical_cli_missing`. If Infisical does not
become ready, it stops with `infisical_readiness_timeout`.
