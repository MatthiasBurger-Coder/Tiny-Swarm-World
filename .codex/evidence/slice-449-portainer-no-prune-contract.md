# S449-PORTAINER-NO-PRUNE — shared stack update safety

Status PLANNED; baseline `29be9194c86a35f448f12f3b7905956dc7a430d2`. Current `PortainerHttpClient.update_stack` sends `prune=True`; direct `PortainerHttpClient.apply_stack` and `LxcPortainerHttpClient.apply_stack` existing-stack paths delegate to it. `tests.infrastructure.adapters.clients.test_portainer_http_client.TestPortainerHttpClient.test_update_stack_sends_prune_payload` currently expects True. The independent lifecycle Portainer adapter already sends false; preserve it. The accepted `documentation/arc42/09_decisions/adr-classic-selection-exposure-stack-ownership.adoc` says ordinary updates cannot prune services. [Portainer API documentation](https://api-docs.portainer.io/?edition=ce&version=2.39.0) describes prune as removal of Swarm services no longer referenced in the stack definition.

## Narrow behavior

Change only the shared HTTP update request's `prune` boolean from True to False, with no caller option to re-enable it. Both direct and LXC-delegated existing-stack updates inherit this setting. Keep request method, endpoint/stack IDs, stack file, `pullImage`, env encoding, authentication, timeout, create behavior and unrelated legacy CLI/runtime logic unchanged. Services no longer present in a submitted stack definition may remain; no automatic removal, full desired-state convergence or safe service-removal guarantee is claimed. A separately reviewed explicit removal flow is needed for deletion.

This reduces automatic removal risk but does not implement accepted optional-stack ownership. `find_stack_id_by_name` currently returns the first name match; endpoint, unique stack, ResourceControl and saved-definition fingerprint ownership are not established by this change. Do not claim this slice supplies those guards, completes S449-05/#449/#440, authorizes a live update or qualifies either host. The independent verified ownership guard and no-competing-writer/convergence work remain separate. No host action is part of this slice.
