# S449-02F10 — reader namespace diagnostic design

Status: PLANNED. F9 source `4adcdfe456afddd881820c9a060a53113a2febfd` produced native `BLOCKED_UNKNOWN / PROC_ROOT`, exit 2; independent private evidence review is required. F9 did not read namespace descriptors. [Kernel cgroup v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html#namespace) states that `/proc/<target>/cgroup` is relative to the reader's cgroup namespace; this neither proves the reason for F9 nor identifies its reader. [Linux namespace ioctl](https://man7.org/linux/man-pages/man2/ioctl_nsfs.2.html), [namespace type ioctl](https://man7.org/linux/man-pages/man2/NS_GET_NSTYPE.2const.html), and [fstatfs](https://man7.org/linux/man-pages/man2/statfs.2.html) define the required checks.

## Fixed contract and observations

Only standalone `--diagnose-snap-reader-namespace` produces exactly two JSON fields: `status` is `BLOCKED_UNKNOWN` and `reason` is `SAME`, `DIFFERENT`, or `UNKNOWN`; exit status is always 2. Duplicate, valued or mixed invocations yield UNKNOWN before host I/O. No bytes, paths, PID, device, inode, hash, exception or raw observation may appear on stdout or stderr. F4–F9 paths and results remain identical.

SAME/DIFFERENT compares only the namespace object of this F10 reader to that of PID 1 visible in its PID namespace. PID 1 must never be assumed to be host or initial namespace. No output establishes the namespace of F9's earlier reader or the target process, membership, security, host admission or mismatch cause. UNKNOWN is mandatory on absent, ambiguous or unstable evidence.

## Bounded trust and recheck

This is an explicit F10-only architecture exception to F9's no-namespace-reads rule. It uses the existing F4 trusted local-root boundary: the procfs anchor and mount view must be trusted, with no hostile concurrent actor holding CAP_SYS_ADMIN who can alter mounts. This is not a claim that arbitrary privileged ABA changes are detectable. Missing trust, mount provenance or uncertain observations produce UNKNOWN. The two logical subjects are the current reader and PID 1 visible in the anchored procfs PID view; no host or initial PID namespace is inferred.

Anchor `/proc` using `O_PATH|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, verify `fstatfs` type `PROC_SUPER_MAGIC` (0x9fa0), and retain the FD. Use only fixed `readlinkat(procfd, "self")`: a bounded in-memory ASCII positive decimal without slash or leading zero, exactly equal to `os.getpid()`, identifies the fixed current reader directory. Reject malformed, mismatched or inaccessible results. Pin that derived numeric directory, fixed `1` and their `ns` directories relative to the anchor with `openat2` and `RESOLVE_NO_XDEV|RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS`; never follow `/proc/self` as an intermediate, never accept user-supplied paths, and never fall back. `statx` with `AT_EMPTY_PATH` and `STATX_MNT_ID` on the anchor and every pinned intermediate FD must return an available, identical mount ID. Keep these FDs open and recheck their identity, filesystem type and mount ID. Capture and recheck the fixed reader and visible PID 1 start identities, and the fixed self link, under the same budget; a missing or changed result is UNKNOWN. The view may be a non-host PID namespace.

For each of the two pinned `ns` directories, open only the exact fixed name `cgroup` with `O_PATH|O_NOFOLLOW|O_CLOEXEC`, then verify with `fstat`/`statx` that it is a symlink on the same mount ID as the trusted procfs root. Retain both link FDs. Follow only those exact fixed names separately using `O_RDONLY|O_CLOEXEC`, retaining namespace FDs; verify `fstatfs` returns `NSFS_MAGIC` (0x6e736673) and `NS_GET_NSTYPE` returns `CLONE_NEWCGROUP` (0x02000000). Hold all FDs; reopen and recheck link and namespace object identities, type, mount IDs, self link, process identities, unit and F9 inputs before returning. These are bounded checks under the stated F4 trust model, not an atomic snapshot or a guarantee against privileged ABA. Any discrepancy, permission error, failed or unsupported syscall, type or identity check is UNKNOWN. `os.fstat` alone establishes neither filesystem nor namespace type. No other target or symlink is allowed.

The only initially supported ABI is Linux x86_64 LP64 with verified libc/kernel layouts: `openat2` syscall 437 with 24-byte `open_how`, resolve bits NO_XDEV 0x01, NO_SYMLINKS 0x04 and BENEATH 0x08; `statx` syscall 332, `AT_EMPTY_PATH` 0x1000, `STATX_MNT_ID` 0x1000, verified 256-byte Linux `struct statx`, and a correctly sized ABI-verified libc `fstatfs` structure. `NS_GET_NSTYPE` is `_IO(0xb7, 0x3)` (0xb703). Layout, machine, syscall availability, mask and return results must all be checked; unsupported or unverifiable ABI means UNKNOWN without fallback or guessed layout. No runtime compilation or external command derives constants. If the specified trust boundary or syscall/structure validation cannot be established, implementation must fail closed without weakening these requirements. Python 3.12 and 3.14 both need compatible stdlib-only behavior.

Bind the validated active unit, its MainPID and process start identity, PID 1 start identity, source and unchanged F9 baseline snapshots; require a reproduced F9 PROC_ROOT. Hold both verified namespace FDs open while comparing in-memory `(st_dev, st_ino)`. Reopen only those two fixed namespace FDs, verify their type and identities against the pinned FDs, recheck PID 1, unit/MainPID/start and all F9 snapshots before deciding. Reject detected PID reuse, source, procfs, type, identity or snapshot drift. Rechecks cannot prove absence of arbitrary ABA changes between observations; hold all available identity-bearing descriptors and reject whenever the required stability cannot be established. Do not claim an atomic observation. The F9 reader is not inferred from this later run. Close every FD on every path. Permissions, exceptions, I/O, raced or incomplete checks, unsupported ABI, budget exhaustion or uncertain provenance give UNKNOWN without revealing details.

At most the bounded F9 queries/rechecks plus fixed self readlink, fixed reader/PID 1 start identity reads and rechecks, procfs directory and final link descriptor checks, and two namespace opens and two reopens are allowed, within 60 seconds and 16 MiB combined F9/F10 budget. No new arbitrary reads, host command, shell, setns, nsenter, sudo, client, socket, network, environment-file, service activation, artifact or mutation is allowed.
