## Authority and inputs

Expose a versioned immutable code-bound policy (`scoped-route-policy-v1`) as the only route mapping authority; no public registry, supplied alternative mapping, trust flag or caller-selected authority. Public callers cannot self-attest stock or reviewed provenance. Inputs must be exactly typed, revalidated v1 `InstallationManifest`, `ComponentCatalog`, selected Swagger exposure and explicit listen IPv4 address. Reuse G2a strict revalidation to reject forged model_construct/model_copy, bad catalog, duplicate identities or missing dependencies; validate exact preset, complete resolved selection and source-policy identity. The pure function cannot read environment or establish the absence of custom/alternate/TSW_INFRA_ROOT overrides. It returns only a deterministic ideal reference for the embedded policy with `runtime_source=UNKNOWN` always; it never claims current applicability or grants admission/execution. Any request/result claiming actual applicability returns `AUTHORITY_GAP`. A future separately reviewed pre-effect adapter must verify effective sources and overrides and block when unknown; caller-provided assertions cannot establish trust.

The implementation must use a fixed reviewed, immutable mapping reflecting the accepted ADR and compare its tuples exactly against the relevant pure domain setup-code assumptions; a mismatch yields AUTHORITY_GAP instead of silently adapting. This is domain-code drift checking only: it cannot detect environment, filesystem, deployed runtime assets or overrides and cannot verify their absence. Reject default preset with selected Traefik/Infisical/service-access, any unknown ID/preset, omitted mandatory incus/portainer, inconsistent catalog/preset/dependency or ambiguous route. In service-access preset the 8086 SetupManifest/ports.yaml ownership conflict blocks **either selected Infisical or selected service-access**, even if caller proposes a route. Do not add, omit or guess 8086.

## Route mapping and profile identity

For allowed selected services, fixed policy includes portainer 10001; nexus 13081/13500/13501; jenkins 11080/11050; pulsar 14001/14080/14081/7750; sonarqube 12000; selected published swagger 16080/16081; selected traefik 80/443 under service-access. Incus has no route. Infisical and service-access affected selections remain blocked until a separate authority decision. All selected-service/preset combinations must produce the complete prescribed map or fixed AUTHORITY_GAP. Internal Swagger suppresses 16080/16081 only when shared ingress is proven inactive; P0 has no host evidence or caller self-attestation, therefore return AUTHORITY_GAP for selected internal Swagger until a separately reviewed trustworthy evidence contract exists. No implicit ingress-isolation or adoption claim.

Each immutable route has canonical service/device ID, protocol TCP, explicit listen `127.0.0.1|0.0.0.0`, validated port, connect `127.0.0.1:<same port>`, `bind=host`, `nat=false`, `proxy_protocol=false`, device `tsw-proxy-<port>`. These flags are policy values, never observed host values. No coercion/whitespace, boolean-as-port, unknown option, duplicate service/port/device or overlapping wildcard/equal-address listeners. Distinct non-overlapping listeners may share a connect endpoint. Wildcard use has separate future consent/firewall/host gates; P0 alone authorizes no route.

Profile algorithm is exactly accepted `profile-name-v1`: existing v1 36-character string accepted by `UUID(value)`, preserve text verbatim, hash `b"tiny-swarm-world/incus-profile/v1\x00" + UUID(value).bytes` via SHA-256, name `tsw-profile-` + first 32 lowercase hex chars. UUID strings with equal UUID bytes produce equal names. Required vectors: all-zero UUID -> `tsw-profile-61b337b53d63c58eab10669c47a35a0b`; `123e4567-e89b-12d3-a456-426614174000` -> `tsw-profile-e175d6395024f2dc3b44dca4aa283506`. No collision/ownership inference. Keep original v1 state and all prior behavior unchanged.
