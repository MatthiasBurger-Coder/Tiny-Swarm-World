## Port and CAS adapter

Add a separate `VersionedManifestRepository` port and typed snapshot carrying either exact V1 or unadopted V2 plus opaque concurrency token, without changing existing `ManifestRepository` or its consumers. Add a dedicated isolated filesystem adapter with strict dual-version read; V1 is validated exactly by the existing V1 codec; V2 follows the closed contract above. Reads never create directories, lock files or perform migration; absent, unknown version, malformed or unsafe path returns typed non-admitting error. V2 writes are explicit CAS operations only in a dedicated isolated staging path, never the canonical live installation manifest and never runtime wiring. The adapter cannot construct or accept `ADMITTED`, and does not execute a migration, reconcile a host or grant consent.

The adapter's only data location is the fixed noncanonical draft `.tiny-swarm-world/staging/manifest-v2-draft.json` relative to one explicitly selected, pinned operator-local root. It must never point at `.tiny-swarm-world/installation/manifest.json` or any caller-selected relative file. Open the root as a directory once and walk `.tiny-swarm-world/staging` through descriptor-relative `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`; no symlink or escape is permitted. Existing root/parents must be owned by the current effective UID and not group/world accessible; staging parents are 0700, draft and fixed lock file are 0600 regular files owned by the effective UID with link count exactly 1; reject symlinks, hardlinks, malformed modes, special files and inaccessible/unknown metadata. Bound each record to 1 MiB with streaming limit; reject overflow before parse or replace. Reads may not create any directories, files or locks; a missing draft returns ABSENT. Any setup needed for writes belongs to the explicit write only, under these same checks.

Concurrency contract is for cooperating clients using the same stable lock inode; trusted operator-local root and no hostile concurrent same-UID or privileged writer are explicit assumptions, not a hostile-actor/ABA-proof claim. The fixed lock is `manifest-v2-draft.lock` in the pinned staging directory, opened `O_CREAT|O_RDWR|O_NOFOLLOW|O_CLOEXEC` without truncate, mode 0600, regular owner-owned single-link; never remove, replace or rename it. Verify its fd/path device+inode binding before and after flock and before commit; if changed, fail closed. Hold the flock and pinned parent through read/compare/write. Two processes using the same token and attempting **different** new records may produce at most one successful write. An exact same-byte write against a matching present token is a no-op success without replacement; a stale token blocks whenever current bytes differ from the bytes represented by that token; an intervening change followed by byte-identical restoration is not detected. Token is internal opaque SHA-256 of exact current bytes; it is not a monotonic generation, so a byte-identical ABA returns the same token and is not detected. ABSENT uses a distinct typed token, never `None` conflated with empty file or a byte hash; explicit create with ABSENT must reject an existing file. Tokens are internal CAS data, never logged or sent to CLI. Read current bytes and token again under lock; compare the exact current pre-write state, not a cached parsed object.

Write a 0600 exclusive random temporary regular file in the same pinned directory; bound content, flush/fsync it, recheck lock/target and perform dirfd-relative atomic replace followed by parent directory fsync. Any error before replace leaves prior final state; after replace but before successful directory fsync return `UNCERTAIN`, never success, blind retry or deletion of final record. Cleanup only the exact securely created temp name when known safe, never an uncertain final. Reopen/read-only inspect to reconcile uncertain outcomes. On mismatch, permission or binding error before replacement, preserve the previous final file. A crash before replacement preserves the previous final; after replacement/crash or failed directory fsync the final may be the complete old file or the complete new file, never a claimed success. Reconcile only by a later read-only inspection; no exception text, token, data, paths or secret values in logs/errors.

## Closed port results and parser bounds

The proposed synchronous port signatures are `read(catalog: ComponentCatalog, exposure: SwaggerMode, listen_address: str) -> ReadResult` and `compare_and_swap(record: UnadoptedV2Record, expected: CasToken, catalog: ComponentCatalog, exposure: SwaggerMode, listen_address: str) -> WriteResult`. `ReadResult` is a closed tagged union: `ABSENT` with the distinct ABSENT token, `PRESENT` with a V1 or strict UNADOPTED V2 record plus opaque bytehash token, or `BLOCKED` with no record/token. `WriteResult` is a closed tagged union `SUCCESS` (including matching same-byte no-op), `CONFLICT` for stale/incorrect present or absent state, `BLOCKED` for invalid input or unsafe observation before replace, or `UNCERTAIN` after possible replacement/durability loss. `SUCCESS` may carry the resulting opaque token; errors carry no path, data, exception or secret. These token/record/snapshot types have explicitly redacted `repr` and string forms, and no logging/CLI serialization exposes them. No implicit None token or success for an uncertain write.

Apply a 1 MiB raw byte cap before JSON parse, reject NaN, Infinity and -Infinity (including nested occurrences), bound nesting depth to 32 and total object members plus array elements to 50,000, and reject duplicate keys at every depth. Enforce complexity bounds during parsing or an equivalent bounded pre-validation so the parser cannot exceed these limits before validation; malformed UTF-8, syntax, recursion, overflow or parser failure returns BLOCKED with fixed safe error. Tests cover caps, excessive depth/item count, duplicate nested keys, non-finite numbers and repr/log/error sentinels.

## Version and validation inputs

V1 decode is exactly the existing `decode_manifest` rules; V2 decode requires an explicitly supplied strictly revalidated `ComponentCatalog`, selected `SwaggerMode`, explicit allowed listen address and a fixed supported `scoped-route-policy-v2`/`profile-name-v1` identity bound to the record. Recompute G2c/P0 from the decoded V1 and those exact typed inputs and compare every desired field/route/version. The catalog snapshot is an input to structural validation, not evidence of its origin or runtime applicability. Missing, forged, mismatched, changed version/catalog/exposure/listen, unknown source or policy mismatch returns BLOCKED/UNKNOWN; no caller-supplied reviewed enum substitutes for authority. Persisted record must include enough typed version/exposure/listen values to compare these exact inputs; reloading with changed catalog or policy may fail closed. A future catalog migration or retained immutable policy snapshot requires a separate decision; this slice never rewrites record on read. UNKNOWN provenance is required and is never admission.
