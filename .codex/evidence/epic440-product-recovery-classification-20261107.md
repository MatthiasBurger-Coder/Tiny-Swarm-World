# Native Windows product recovery versus qualification evidence — accepted authoring boundary

Scope: only the existing W05 resource action required for Epic 440's named PC
WSL target. Independent requirement/workflow, architecture/security and tester/DevOps
reviews accepted proposal 506e1d1e313dad5c01723f9db9d524e4879494e71cf483aa4087259c42d3f038.
Root records this explicit boundary in the active issue workflow. No host
action is released by that authoring acceptance.

The accepted Capacity-aware WSL Resource Preparation ADR requires protected
original .wslconfig bytes and metadata for restoration. The shipped resource
adapter and preparation ports create Windows-native runtime recovery state.
The issue-449 evidence policy currently permits only four named human-only
NTFS files and otherwise requires private ext4 evidence; it does not explicitly
classify these native product artifacts. Sanitized console output does not
resolve that persistence conflict.

Accepted bounded classification: the following are native product operational
state/recovery artifacts, not S02 fixture-runner admission/evidence files:
- Under the existing product-selected LocalAppData/TinySwarmWorld/preparation:
  bootstrap.state.json, bootstrap.lock, private GUID.json intent/effect/backup
  metadata, wslconfig-GUID.backup and their uniquely named transaction temps.
- Under the already validated Windows user-profile configuration directory:
  the original .wslconfig, .tsw-wslconfig.lock, unique .tsw-wslconfig-GUID.tmp,
  and retained .tsw-displaced-GUID.backup generated by the existing adapter.

Only the existing Windows product adapter may create/update these paths during
a separately reviewed exact source/host/distro/fingerprint resource-only GO.
Preserve current-user/SYSTEM/Administrators protection, original file metadata,
no-reparse/owner checks, locking, exclusive backup creation, snapshot/drift
checks, atomic replacement and final backup/displaced verification. No raw
unrelated configuration, ACL/SDDL/SID or backup paths may enter console,
repository, exported reports or fixture control artifacts. Original ACL and
metadata needed for restoration may remain only in the protected native product
recovery records. The .wslconfig target itself retains its validated original
ACL/metadata as required by the ADR; this is not an ACL-widening permission.
Do not delete/adopt unexplained existing state/locks/backups to force progress.

All issue workflow GO/review/plan/reservation/capture/result records and sanitized
audit evidence still require approved ext4 storage, directory 0700/file 0600.
The native recovery files never serve as fixture GO, supported-version evidence
or source authority. Workflow records may bind only safe source/plan/config/
backup digests and typed state/result flags; operator-only recovery resolves
actual backup locations in the native protected store. Historical broad-ACL
NTFS issue evidence remains forbidden. The four earlier human-only exceptions
are unchanged and confer no runtime authority.

This explicitly supersedes only the evidence policy's lack of classification
for these required W05 native product artifacts. It does not authorize Apply,
WSL shutdown/start, a service/task change, bridge reconciliation, firewall or
PortProxy change. Each requires its separate phase-specific admission/GO;
existing user preservation requirements remain. In particular, a Running
TinySwarmWorldWslBridge was observed and can rewrite PortProxy after WSL IP
changes: no preservation exception is inferred from this classification.

Independent reviews accepted the exact proposal before this active workflow
amendment; final authored bytes are reviewed separately before checkpoint.
No source/ADR decision or durable recovery engine change is proposed.
