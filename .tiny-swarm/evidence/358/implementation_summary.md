# Issue #358 implementation summary

The command entrypoint retains argument parsing, confirmation and live-consent prompts, dependency binding through composition, output selection and exit mapping. It delegates workflow execution to `infrastructure/composition_cli.py`, which invokes explicit application workflow services through `application/services/cli_dispatch.py`. Host preparation now uses `PrepareHostWithPreflight` so preflight completes before the mutating host adapter is resolved. The guided setup preview is built from the compose repository by `build_setup_installation_plan` and rendered by `cli_presentation.py`. Existing command names, safety prompts and exit semantics are retained.

The CLI regression tests freeze all 19 supported workflow names and verify that every mutating workflow exits 2 without live consent. Existing consent, destructive confirmation, output and success/failure exit tests remain in `tests/test_package_entrypoint.py` and `tests/test_classic_update_cli.py`. A focused host use-case test verifies that failed preflight never resolves the mutating adapter. The local lint and typecheck gates now include the CLI entrypoint and presentation module.
